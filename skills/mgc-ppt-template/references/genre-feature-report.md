# 기능 보고형(사내 중간 보고, 기능 소개, 개발 요청 공유)

기준 덱: 「신규 오픈 매장 프로모션 고도화 3개 기능 중간 보고」 개선본(2026-10-02, 6장). 공통 기준은 `references/design-common.md` · `references/writing.md` · `references/text-fit.md`를 따른다.

## 재현 원칙

- **`scripts/mgc_report.js`를 그대로 써서 만든다.** 좌표 · 색 · 글자 크기를 새로 작성하지 않는다. 문구 · 이미지 · 패턴 선택만 함수 인자로 넣는다.
- `mgc_report.js`는 고치지 않는다. 기준 덱을 실측한 값이라, 고치면 덱마다 레이아웃이 달라지고 `compare_layout.py` 비교가 무의미해진다. 부품이 부족하면 임의로 고치지 말고 사용자에게 패턴 추가를 제안한다.
- 본문은 아래 「본문 패턴 A~F」 중에서만 고른다. 각 패턴의 호출값(y · h · gap 등)은 표에 적힌 값을 그대로 쓴다.
- 기준 덱 1장의 기간 문구는 기준점 규칙(`references/writing.md` 「값 표기」)대로 고쳐 쓴다.
- 재현 검증 결과(2026-10-02): 기준 개선본 6장을 `example_interim_report.js`로 다시 만들었다. 도형 216개 중 215개가 좌표 · 색 · 글자 서식에서 일치했다. 다른 1개는 6장 각주 폭을 12.33에서 9.0으로 줄여 오른쪽 아래 쪽 번호와 겹치지 않게 한 의도적 수정이다.

## 제작 절차

1. **장 설계**: 기능을 실제 진행 시점 순서로 나열한다. 개발 요청 번호 순서가 아니다.
   - 기능마다 2장을 둔다: '기능 소개' 1장 + '화면 상세' 1장.
   - 단계 정의를 쓴다: `[n단계 · 시점, 내용]`.
   - 단계는 1~4개까지 쓸 수 있다. 흐름 헤더 폭은 단계 수에 맞춰 자동으로 나뉘고, 글자 수 한도는 아래 「글자 수 한도」의 단계 수별 값을 따른다.
   - 5개 이상은 한 줄에 읽히는 폭이 나오지 않아 `createDeck`이 오류를 낸다. 시점이 같은 기능을 한 단계로 묶거나(단계 안에서 장을 늘림), 덱을 나눈다.
2. **패턴 선택**: 기능 소개 장은 A · C · E 중 하나, 화면 상세 장은 B · D · F 중 하나.
3. **이미지 준비**: 아래 「화면 이미지 준비」에 따라 화면안을 PNG로 잘라 둔다.
4. **스크립트 작성**: `example_interim_report.js`를 복사한 뒤 문구 · 이미지 경로만 바꾼다. 「글자 수 한도」를 참고해 줄을 직접 나눈다.
5. **생성 · 검수**: `node 생성스크립트.js out.pptx`로 생성하고 `python3 pptx_edit.py finalize out.pptx out.pptx`를 실행한 뒤 `references/qa-checklist.md`를 수행한다. 줄 탈락 오류로 멈추면 `references/text-fit.md` 「넘칠 때 고치는 순서」의 새로 생성 행을 따른다.

## 구성 규칙

- 배경은 전부 white로 한다. 샌드위치 구조는 적용하지 않는다.
- 상단 표시는 'n단계'로 쓴다(기준 덱은 1~3단계). '기능 n'은 쓰지 않는다. 개발 요청 번호는 발표자 노트에만 쓴다(`references/final-deliverable.md` 「발표자 노트」).
- 공수 · M/D · 기술 분석 · 개발사 확인사항은 넣지 않는다.
- 첫 장(기능 소개)에만 진행 현황을 쓴다. 형식: `진행 현황: M/D(요일) 개발 요청 발송 · 상태  |  운영 담당: 부서(역할)`.
- 모든 장 오른쪽 아래에 `YYYY-MM-DD 중간 보고 · n / N`을 넣는다. `save()`가 자동으로 넣는다.

## 본문 패턴 A~F(호출값 고정)

| 패턴 | 용도 | 호출(`mgc_report.js` 함수) | 제약 |
|---|---|---|---|
| **A** 화면 3 + 설명 3 | 기능 소개: 고객이 보는 변화 | `phones({y:1.95, h:4.0, gap:0.45})` + `label('한눈에 보기', {x:7.6, y:1.95, w:5.0, size:16})` + `points({y:2.6, gap:1.25})` | 휴대폰 화면 3개, 캡션 + 설명 |
| **B** 화면 3 + B.O 캡처 + 라벨 표 | 화면 상세: 추가 적용 위치 + 운영 방법 | `phones({y:1.95, h:3.55, gap:0.35})`(설명 없이 캡션만) + `capture({x:6.63, y:1.95, w:6.2, captionBold:true})` + `labelTable({x:6.63, y:캡처하단+0.55, w:6.2, colW:[1.7,4.5]})` | 라벨 표 3행 |
| **C** 흐름 박스 + 화면 3(화살표) + 설명 3 | 기능 소개: 고객 여정 | `flowBoxes({y:1.95, h:0.85, key:결과 단계})` + `phones({y:3.05, h:3.1, gap:0.6, arrows:true})` + `label({x:7.6, y:3.1, w:5.0, size:16})` + `points({y:3.65, gap:1.05})` | 흐름 박스 5칸, 노랑 1칸 |
| **D** 상황 표 + B.O 캡처 + 키-값 | 화면 상세: 예외 상황 + B.O 설정 | `label({x:0.5, y:1.95})` + `headTable({x:0.5, y:2.42, w:6.0, colW:[2.2,3.8], rowH:[0.42, 0.55×(n−1), 마지막 2줄 행 0.75]})` + `label({x:6.85, y:1.95})` + `capture({x:6.85, y:2.42, w:5.98})` + `kvList({x:6.85, y:캡처하단+0.2, w:5.98})` | 표 6행 이내, 키-값 4행 이내 |
| **E** 단계 카드 4 + 가로 캡처 | 기능 소개: 운영자 작업 순서 | `label({x:0.5, y:1.9})` + `stepCards({y:2.35, h:1.55, key:마지막})` + `capture({y:4.35, w:12.33, caption})` | 캡처 가로세로비 ≥ 7(높이 1.75 이하) |
| **F** 가로 캡처 + 번호 카드 5 | 화면 상세: 화면안 번호별 설명 | `capture({y:1.9, w:12.33})` + `numberCards({y:캡처하단+0.35, h:1.75, footnote})` | 캡처 가로세로비 ≥ 4.9(높이 2.52 이하), 각주 하단 ≤ 7.0 |

- 같은 줄 휴대폰 화면은 폭을 통일한다. 첫 이미지 비율을 쓰거나, `ratio`로 지정한다. 기준 덱 1단계는 197/420이었다.
- 패턴 C의 화면 설명 줄은 진행 현황 줄과 같은 높이대에 놓인다. 그래서 설명은 1줄로 쓴다.

## 화면 이미지 준비(`crop_screens.py`)

- 개발 요청 메일 · 기획서에 첨부된 화면안을 잘라 쓴다. 새로 그리지 않는다. PNG로 저장한다(코드가 PNG 크기를 읽음).
- 휴대폰 화면은 상태바부터 화면 하단까지 자른다. 다른 화면의 화살표나 주석이 같이 잘리지 않게 2~5px 안쪽으로 자른다.
- 잡티는 주변 배경색으로 덮는다: 붙여넣기 아이콘, 화살표 조각, 페이지 주석, 보라색 배경 띠 등. 흰색으로 덮지 말고 실측한 배경색을 쓴다(예: 248,248,248).
- 표 화면이 작아 읽히지 않으면 머리부와 4~6행만 잘라 폭 12.33으로 키운다(패턴 F).
- 이미지 대체 텍스트는 `alt`에 화면 설명을 넣는다. 파일 경로가 들어가면 안 된다.

## 글자 수 한도(`fit_text.js` · `check_text.py`가 자동 검사)

판단 기준은 글자 수가 아니라 줄마다의 추정 폭이다. 아래는 **한글만 쓴 경우** 한 줄에 들어가는 글자 수로, 문구를 쓸 때 참고한다. 공백 · 영문 · 숫자 · 기호는 한글보다 좁아서 섞이면 더 들어간다. 최대 줄 수를 넘기려면 문구를 줄인다.

| 위치 | 한 줄(한글 기준) | 최대 줄 수 |
|---|---|---|
| 제목 | 35자 | 1줄 |
| 목적 문구 | 71자 | 1줄(한 문장) |
| 진행 현황 | 62자 | 1줄 |
| 장 구분 칩 | 7자 | 1줄 |
| 휴대폰 캡션(화면 h 4.0 / 3.55 / 3.1) | 12 / 11 / 10자 | 1줄 |
| 휴대폰 설명(화면 h 4.0 / 3.55 / 3.1) | 15 / 14 / 12자 | 2줄 |
| 설명 순번 제목 / 설명 | 23자 / 28자 | 1줄 / 3줄(gap 1.25), 2줄(gap 1.05) |
| 흐름 박스(5칸) | 11자 | 3줄 |
| 단계 카드 제목 / 설명(4칸) | 9자 / 15자 | 1줄 / 3줄 권장 |
| 번호 카드 제목 / 설명(5칸) | 9자 / 11자 | 1줄 / 2줄 권장 |
| 머리행 표 1열 / 2열(colW 2.2 / 3.8) | 11자 / 21자 | 행 높이 0.55에 2줄 |
| 라벨 표 1열 / 2열(colW 1.7 / 4.5) | 8자 / 25자 | 행 높이 0.46에 1줄 |

| 캡처 캡션 / 각주 | 78자 / 56자 | 1줄 |

흐름 헤더는 단계 수에 따라 글씨 폭이 달라진다(한글 기준, 1줄 = 단계 · 시점, 2줄 = 내용).

| 단계 수 | 1줄 | 2줄 |
|---|---|---|
| 1 | 79자 | 66자 |
| 2 | 36자 | 30자 |
| 3(기준 덱) | 23자 | 19자 |
| 4 | 16자 | 13자 |

- 4단계에서는 2줄 내용이 짧아진다. 기능 설명을 줄이지 말고 결과만 남긴다. 예: "매장 QR로 'MY매장' 등록 + 쿠폰 지급" → "매장 QR로 'MY매장' 등록".

# 최종본 · 산출물 규격(사용자에게 넘기는 파일)

처음 문서를 보는 사람(개발사 · 타부서)은 다듬은 과정을 모른다. 전 · 중 · 후가 섞이면 오히려 헷갈리므로 **최종 정책 · 기능 · 흐름만** 쓴다. 기준 덱: 「최애 메뉴 부활 투표」 기획서 통합본 v0.2(표지 포함 37장).

## 버전 표기

- 확정 전에는 모든 산출물(기획서 · PRD · 프로토타입 · 검증 스크립트)의 파일명 · 표지 · 노트 · 기준 자료 표기를 **같은 버전 문자열로 통일**한다. 기획서 기본값은 v0.2이고, 수정해도 버전은 올리지 않고 파일명 날짜만 바꾼다. 확정되면 v1.0으로 승격한다.
- 표지 문서 종류 줄은 '문서 종류 + 버전'만 쓴다(예: "앱 이벤트 기획서 v0.2"). "1차 확정" · "수정본" · "확정 시 v1.0" 같은 상태 문구는 넣지 않는다.
- 표지 날짜 줄: `YYYY-MM-DD · 부서 · 핵심 기간`(예: "2026-10-20 · 마케팅1팀 서비스기획 · 투표 2026.11.23(월) ~ 12.06(일)").

## 작업 이력 금지

본문 · 표 · 핵심 한 줄 · 발표자 노트 모두에 적용한다.

- 피드백 날짜, "피드백 반영", "~를 제거 · 대체 · 변경 · 폐기", "(현행 동일)", 대안 서열 · 결정 경위, 공수 절감 사유를 쓰지 않는다. 이력은 업무 이관 문서(`work-handoff-prompt`)에만 남긴다.
- **없어진 것은 언급하지 않는다.** "오픈 전 화면 없음", "문구 분기 없음" 대신 최종 규칙을 긍정형으로 쓴다("노출 시작 = 투표 시작", "회차와 관계없이 같은 문구").
- 미정 항목은 확인 태그로만 쓴다(`references/writing.md` 「확인 태그」).

## 결정 과정 미노출

- 확정된 정책은 최종 기준만 쓴다. 선택지 · 추천안 · 1~3순위 · 「○○ 권고와 같음」 · 「결정 ○번」 · 「(확인 중)」 · 「공수가 적정하면 도입」 같은 판단 문구를 남기지 않는다.
- 결정 장은 「정책 기준 N가지」(항목 | 기준 | 비고)로 쓰고, 항목이 빠지면 N과 이를 가리키는 모든 문장 · 간지 목록을 같이 고친다.
- 쓰지 않기로 한 기능 · API는 흔적 없이 지운다(번호 · 표 행 · 흐름도 단계 · 용어 · 부록 불일치 행 · 흐름도 이미지까지). 꼭 설명이 필요하면 번호 원본 장 각주 1줄로만 쓴다(예: "로그인 유지는 자체 토큰으로 처리해 토큰 인증 API는 쓰지 않음").
- 문서 전반의 결론이 바뀌면 개요 수치(예: API 11종 → 9종), 목차 설명, 간지 설명, 핵심 한 줄까지 같은 값으로 맞춘다.

## 같은 규칙 · 모순 대조

- **같은 규칙은 모든 위치에 같이 쓴다.** 한 규칙을 고치면 그 규칙을 설명하는 모든 장(구조 · 기능 · 로직 · 체크리스트 · 용어)과 PRD를 함께 고친다.
  - 대칭 규칙은 양방향을 모두 적는다. 예: "한쪽을 고르면 0.3초 뒤 다른 탭으로 이동 / 음료 → 푸드, 푸드 → 음료 모두 같음".
  - 고친 뒤 핵심어로 전체 텍스트(노트 포함)를 검색해 옛 표현이 남지 않았는지 확인한다.
- **모순 대조**: 장끼리 조건이 충돌하지 않는지 비교한다. 예: 앱 푸시 장 "마지막 날 달성분 08시 발송 취소" vs Braze 장 "마지막 날 미발송" → 한 표현("마지막 날 달성분은 발송 대상 아님")으로 통일.

## 보고 구조

- 정해진 기준(「정책 기준 N가지」)은 개요 영역에 두고, 마지막 「확인 필요」 영역에는 열린 항목만 둔다.

## 발표자 노트

모든 장에 `notes`로 남긴다.

- 첫 줄에 근거를 쓴다. 간결 기획서형: "근거: 프로토타입 v0.2 · PRD v0.2."처럼 기준 산출물과 버전. 기능 보고형: 개발 요청 메일 발송일.
- 이어서 그 장의 최종 규칙, 개발 요청 번호(있을 때), 예시값 여부, 확인 필요 부서만 쓴다.

## 산출물 세트

사용자가 "산출물 세트"를 요청하면:

- 구성: 기획서 pptx + PRD docx(`work-writing-patterns`의 PRD 구성) + 프로토타입 html + 검증 스크립트 py + 이관 md.
- 파일명: `[번호]) 메가MGC커피_[프로젝트]_[산출물]_v0.2_YYMMDD`(번호는 사용자 폴더의 기존 체계를 따름).
- PC 저장은 `dated-folder-save`로 오늘 날짜 폴더에 둔다. 같은 날 다시 저장하면 새 파일명으로 저장하고, 예전 파일 삭제는 사용자에게 알리기만 한다.

## docx 동기화

- docx에도 `references/writing.md`의 문체 · 기호 · 강조 · 확인 태그 규칙을 그대로 적용한다.
- docx 전용 값(`references/writing.md` 보완): 글머리 내어쓰기 = 글자 크기 × 0.68, 제목 · 그림 설명의 「 — 」 → 「: 」.
- 처리한 칸은 요소(`_tc`) 집합으로 기억해 두 번 바꾸지 않는다.

## 점검

- 전체 텍스트(노트 포함)에서 "반영 · 제거 · 대체 · 변경 · 폐기 · 1차 · 확정 시 · v1." 등 이력 표현과 옛 버전 문자열을 검색해 0건인지 확인한다(정책 문구로 쓰인 "변경 불가" 같은 단어는 예외).
- 나머지 항목은 `references/qa-checklist.md` 「최종본」.

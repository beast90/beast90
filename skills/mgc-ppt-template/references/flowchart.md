# 흐름도 장(간결 기획서형)

기준 덱: 「신규 오픈 매장 프로모션 고도화 중간 보고」(표지 + 9장). 흐름도는 `scripts/flow_parts.js` 부품으로만 그린다.

## 논리 검수

흐름도 장은 만든 뒤 장마다 한 번씩 아래 9항목을 확인하고 고친다. 고친 내용은 답변에서 표(장 · 문제 · 고친 내용)로 알린다.

1. **처리 순서 = 요구사항 순서**: 요구사항에 처리 흐름(예: 매장 확인 → 등록 → 쿠폰 판단 → 화면 → 안내)이 있으면 상자 순서를 그대로 따른다. 화면 노출 상자를 판단보다 앞에 두지 않는다.
2. **성립하지 않는 분기 제거**: '아니요'로 가면 그 화면 자체가 없는 판단(예: 매장 미노출인데 '일반 표시')은 빼고, 시작 상자 조건으로 옮긴다.
3. **판단 문구가 모든 경우를 맞게 가르는지**: 이미 처리된 대상이 잘못 걸리는지 본다(예: 이미 등록된 매장이 '한도 초과'로 빠짐 → '새 등록 한도 초과?'). 예외는 상자 글에 "(이미 등록 매장은 생략)"처럼 적는다.
4. **막다른 길 없음**: 모든 판단은 나가는 길 2개 이상에 분기 이름이 있고, 시작 · 끝 · 안내 상자가 아닌 상자는 다음 상자로 이어진다. 검증 실패 · 오류 안내는 "수정 후 다시 …" 되돌림 화살표로 입력 단계에 연결한다.
5. **모이는 지점 명시**: 여러 결과가 같은 화면 · 안내로 모이면 화살표로 합치거나 핵심 한 줄로 밝히고, 결과별 안내는 표(결과 × 조건)로 정리한다. 버튼을 누른 뒤 처리(예: [알림 받기])도 표 행으로 넣는다.
6. **진입 경로 일반화**: 사용자 진입이 여러 경로면 시작 상자에 모두 쓴다(예: "쿠폰 화면 진입(푸시 · 직접)"). 앞 단계의 선택 행동(푸시 발송)이 유일한 경로처럼 보이지 않게 한다.
7. **시간이 떨어진 처리**: 나중에 일어나는 처리(예: N일 후 발급)는 같은 줄 오른쪽 별도 상자로 두고 조건(진입 시 · 대상 제외)을 상자 글이나 노트에 쓴다.
8. **분기 이름 배치**: 주 흐름(오른쪽)은 '예', 예외(아래)는 '아니요'가 되게 판단 문구를 정한다(예: '이미 받음?' → '처음 받음?'). 왼쪽으로 가는 짧은 분기는 한 글자 이름('예')만 쓴다. 분기 이름이 옆 상자와 겹치면 문구를 바꾸거나 상자를 옮긴다.
9. **번호 대응**: 상자 속 요구사항 번호(①~⑬, 요건 1~12)가 근거 문서와 맞는지, 장 노트 첫 줄 근거와 같은지 본다.

## 부품 · 배치

| 모양 | 의미 | 서식 |
|---|---|---|
| 둥근 상자(다크 3B2A20, 흰 굵은 글) | 시작 · 끝 · 다음 장으로 이어짐 | 장마다 시작 1개 + 끝 1~2개 |
| 상자(soft F3EEE8) | 앱 · 서버 · B.O 처리 | 요구사항 번호를 글 끝에 |
| 마름모(흰 바탕, 다크 1pt 테두리, 굵은 글) | 판단 | 글 2줄 이내, 줄당 8자 안팎, 끝에 '?' |
| 상자(흰 바탕, muted3 A6968A 1pt 테두리) | 손님 · 운영자에게 보이는 안내 · 오류 | 화면 문구는 프로토타입 원본 그대로 작은따옴표 |

- 글자 크기(이 값 아래로 내리지 않음): 상자 11pt(판단 마름모 굵게), 분기 이름 10pt 굵게, 보조 설명 11pt.
- 범례: 모양 4종 + 이름을 영역 이름 줄(y 0.42) 오른쪽에, 오른쪽 끝 12.73 기준으로 둔다.
- 5열 격자: 상자 폭 2.1, 열 중심 x = 0.6 + 1.05 + i × (12.13 − 2.1) / 4(i = 0~4), 판단 높이 0.85, 처리 높이 0.66. 열 사이 0.41에 화살표 + 분기 이름이 들어간다.
- 행 간격 1.0~1.15in. 한 장 최대 5행(y 2.35 · 3.35 · 4.3 · 5.25 · 6.3). 본문 하단 6.85 이내.
- 보조 설명은 항목이 여럿이면 줄마다 「- 」(`references/writing.md` 「기호」).
- 배치 3종(겹침 없이 통과):
  - **ㄹ자 흐름**: 1행 왼→오, 끝 열에서 아래로 꺾어 3행 오→왼, 다시 아래 5행 왼→오. 예외 상자는 판단 바로 아래 행.
  - **두 구역**: 위 구역(B.O · 운영) / 아래 구역(앱 화면 판단)에 11pt 굵은 구역 이름. 여러 '아니요'가 모이는 결과는 해당 열 폭을 덮는 넓은 상자 1개.
  - **세로 흐름 + 오른쪽 표**: 왼쪽 x 0.6~3.4 세로 흐름(간격 0.1, 판단 뒤 0.25), 오류 상자는 판단 오른쪽(중심 x 5.15), 되돌림 선은 x 6.75로 올라가 입력 단계 오른쪽에 붙임. 오른쪽 x 7.25~12.73에 규칙 표 + 핵심 한 줄.
- 흐름도 아래 결과 × 조건 표를 둘 때: 핵심 한 줄(h 0.42, 15pt) 아래 0.1, 표 행 0.4 · 11pt.

## 사용 예(`flow_parts.js`)

좌표 · 색 · 글자 크기는 고치지 않고 `N()` · `edge()` 인자로만 내용을 넣는다.

```js
const { deck } = require('./slim');
const D = deck('제목');
const { N, edge, legend, note, g } = require('./flow_parts')(D);
const s = D.slide({ sec: '2단계 · …', title: '…', msg: '…', notes: '근거: …' }); legend(s);
const a = N(s, 'end', 0, 2.45, '손님이 홍보물\nQR 스캔 ①');
const b = N(s, 'dec', 1, 2.45, '앱\n설치됨?');
const c = N(s, 'scr', 1, 3.6, '설치 후 QR 다시\n찍기 현장 안내');
edge(s, a, 'r', b, 'l'); edge(s, b, 'b', c, 't', { lab: '아니요' });
// 합류: 상자 오른쪽 → 열 사이(g) → 위 행 주 흐름 선으로
edge(s, c, 'r', { x: g(1, 2), y: 2.45 + 0.02 }, 't', { via: [{ x: g(1, 2), y: 3.6 }] });
note(s, '- 정보 1\n- 정보 2', { x: 0.6, y: 5.6, w: 4.6, h: 0.55 });
// 개요 장 단계 연결 박스: 'n단계:'만 굵게 → addText runs [{text:'1단계: ', bold}, {text:'…', breakLine}, {text:'…'}], fit()으로 폭 검사
```

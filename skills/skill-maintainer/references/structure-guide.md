# 구조 기준 · 템플릿

## 참조 파일 나누는 기준

1. **함께 읽는 단위로 나눈다.** 한 작업(예: 새 덱 만들기 · 사용자 판 고치기 · 최종본 넘기기)에서 같이 필요한 규칙을 한 파일에 둔다. 작업마다 SKILL.md + 참조 파일 2~4개만 읽으면 되게 한다.
2. **모든 작업에 쓰는 규칙은 공통 파일**(디자인 · 문구 · 줄 맞춤 등 성격별 1개씩)로 둔다.
3. **장르 · 문서 유형 전용 규칙은 그 장르 파일**에 둔다. 공통 파일에 장르 전용 값이 섞이면 위계 오류다.
4. **절차 · 검수는 분리**한다. 규칙 파일은 「무엇」, 절차 절은 「순서」, 검수 파일은 「확인 문장 + 기준 위치」만 쓴다.
5. 파일이 300줄을 넘으면 주제로 다시 나눈다. 반대로 30줄 미만 파일이 여러 개면 함께 읽는 파일끼리 합친다.

## 무엇을 어디에 쓰나

| 내용 | 위치 |
|---|---|
| 언제 이 스킬을 쓰는가(트리거) | SKILL.md 앞머리 description |
| 작업별로 읽을 파일, 분기 기준, 우선순위, 규칙 위치 지도 | SKILL.md |
| 모든 작업에 항상 적용하는 규칙 | SKILL.md에는 1줄 요약 + 기준 위치, 본문은 공통 참조 파일 |
| 규칙 본문 · 값 · 예외 · 예시 | 기준 위치 참조 파일 1곳 |
| 실행 코드 | `scripts/` |
| 버전별 변경 내용 · 옛 값 | `CHANGELOG.md` |
| 기준값 · 금지어 · 주제별 기준 위치(기계 점검용) | `lint.json` |

## 문장 쓰는 법

- 규칙은 「조건 → 행동」으로 쓴다: 「표 설명 열은 정보가 1개여도 「- 」로 시작한다」.
- 값은 단위와 함께 한 곳에만 쓴다. 다른 곳은 「기준 위치」를 가리킨다.
- 예외는 규칙 바로 아래 하위 항목으로 쓴다. 다른 절에 흩어 쓰지 않는다.
- (×) / (○) 예시는 규칙 바로 아래에 두고, 예시가 다른 규칙(문체 · 명칭)을 어기지 않게 한다.
- 이유는 짧게 한 번만 쓴다(「~ 사고 방지」). 사고 경위 · 날짜는 CHANGELOG에 쓴다. 단, 같은 실수를 막는 데 꼭 필요한 사례 1줄은 규칙 아래에 둔다.
- 괄호 속 버전 꼬리표, 「추가 규칙」 · 「보완」 같은 덧붙이기 절을 만들지 않는다.

## SKILL.md 템플릿

```markdown
---
name: "<스킬 이름>"
description: "<무엇을 할 때 적용 — 핵심 기능 — 트리거 문구>"
---

# <스킬 제목> (vX.Y, YYYY-MM-DD)

이 파일은 읽기 지도다. 규칙 본문은 `references/`에 주제별로 한 곳씩만 있다.
- 전제(다른 스킬 · 실행 환경 · 복사 방법)

## 작업별로 읽을 파일
| 지금 하는 작업 | 먼저 읽을 파일 | 함께 읽을 파일 |

## 분기(장르 · 유형 고르기)
| 조건 | 선택 |

## 항상 적용하는 규칙(요약 · 본문은 기준 위치)
| 규칙 | 기준 위치 |

## 규칙이 겹칠 때 우선순위
1. 사용자의 이번 요청 …

## 규칙 위치 지도
| 주제 | 기준 위치 |
### 스킬을 고칠 때(skill-maintainer 절차 · 점검 명령)

## 번들 파일
| 파일 | 역할 | 언제 쓰나 |
```

## 참조 파일 템플릿

```markdown
# <주제>(<적용 범위>)

<기준 자료 1줄. 다른 파일과의 관계 1줄: 공통 기준은 `references/x.md`를 따른다.>

## <규칙 묶음 1>
- 규칙(조건 → 행동)
  - 예외
  - (×) … → (○) …

## <절차>(있을 때)
1. …

## <사용 예>(코드 20줄 이내)
```

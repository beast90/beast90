# 수동 점검 항목

점검기(`scripts/skill_lint.py`)가 찾지 못하는 위계 · 논리 문제를 읽으며 확인한다. 찾은 문제는 진단표(유형 · 위치 · 내용 · 처리안)로 적는다.

## 위계

- [ ] 상위 제목이 하위 내용을 모두 포괄하는가(「공통」 절에 장르 전용 값이 없는가)
- [ ] 한 절에 한 주제만 있는가(규칙 · 절차 · 검수 · 이력 · 코드가 한 절에 섞이지 않았는가)
- [ ] 「가장 먼저 읽을 것」 같은 절이 사실상 색인 노릇을 하면서 일부 장르 규칙만 담고 있지 않은가
- [ ] 제목 깊이가 3단(## · ### · ####) 이내인가
- [ ] 같은 수준의 절끼리 나누는 기준이 같은가(예: 장르별 절 사이에 문서 유형 절이 끼지 않았는가)

## 논리

- [ ] 정의하기 전에 쓰는 용어 · 부품 이름이 없는가
- [ ] 절차 순서대로 따라 하면 필요한 파일 · 값이 앞 단계에서 이미 나왔는가
- [ ] 규칙마다 적용 범위(장르 · 문서 유형 · 생성/편집 상황)가 문장에 있는가
- [ ] 「항상」 · 「모든」 규칙에 실제로 예외가 있으면 그 예외가 규칙 바로 아래 있는가
- [ ] 예시가 같은 스킬의 다른 규칙(문체 · 명칭 · 기호 · 끝선 값)을 어기지 않는가
- [ ] 검수표 항목이 모두 기준 규칙을 가리키고, 기준 규칙 없는 검수 항목이 없는가

## 중복

- [ ] 같은 규칙을 2곳 이상에서 쓰는가 → 기준 위치 1곳만 남기고 나머지는 가리키기로
- [ ] 요약(SKILL.md)과 본문이 다른 값을 쓰는가 → 요약에서 값을 빼고 기준 위치만 남김
- [ ] 같은 명령(검사 스크립트 실행 등)을 여러 절차에서 반복하는가 → 검수 파일 1곳

## 모순 유형

| 유형 | 예 | 해소 |
|---|---|---|
| 값 충돌 | 본문 하단 6.85 vs 6.9 | 같은 대상인지 확인 → 같으면 하나, 다르면 대상을 나눠 표로 |
| 범위 충돌 | 「글자 크기는 줄이지 않음」 vs 「10.5pt까지 줄임」 | 적용 상황(생성 · 편집)을 열로 둔 표 하나 |
| 순서 충돌 | 넘침 처리 순서가 절마다 다름 | 상황별 순서 표 하나 |
| 예시-규칙 충돌 | 개조식 규칙 옆 예시가 「~합니다」 | 예시를 규칙에 맞게 고침 |
| 신구 충돌 | 옛 표기(「[확인필요(부서)]」)가 다른 절에 남음 | 최신 규칙으로 통일, 옛 값은 CHANGELOG에만 |
| 문서-코드 표류 | 문서는 FF0000, 코드는 F53148 | 코드가 최신이면 문서를, 문서가 최신이면 코드를 고침. 판단 불가면 사용자 확인 |
| 명칭 충돌 | 금지한 명칭을 예시에서 사용 | 금지어를 `lint.json`에 넣어 재발 방지 |
| 절차 충돌 | 「스크립트에 역반영 후 재생성」 vs 「다시 생성하지 않고 직접 편집」 | 기본 절차 1개 + 다른 절차를 쓰는 조건 명시 |

## 보존 대조

재편 뒤 원문 규칙이 빠지지 않았는지 확인한다.

1. `python3 scripts/coverage_check.py <원본 SKILL.md> <새 스킬 폴더> --until <변경 이력 시작 줄>`
2. 출력된 원문(포함률 85% 미만)을 하나씩 분류한다.
   - 옮김: 표 · 가리키기로 표현만 바뀜
   - 의도적 대체: 충돌 해소로 값 · 문장을 바꿈 → CHANGELOG에 있는가 확인
   - 삭제: 사유를 보고(색인 문장, 중복 문장 등). 규칙이면 삭제하지 않고 되살린다
3. 분류 결과 요약(옮김 n · 대체 n · 삭제 n)을 보고에 넣는다.
